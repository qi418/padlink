# PadLink 技术规格（iPhone 通知流转到 Oppo Pad 4 Pro）

版本：v1.0 ｜ 2026-11-23 ｜ 状态：一期（最小验证包）实施依据

---

## 1. 项目目标

- 核心：iPhone 16 Pro Max 的通知（全部 App）**实时**流转显示到 Oppo Pad 4 Pro（Android 15 / ColorOS 15）。
- 双端后台常驻、省电、自动重连。
- 平板端可直接查看通知全文；点击通知可打开平板本地的微信/QQ（用户已确认在平板登录同账号）。
- 交付：平板 App（APK）、iPhone 助手 App（ipa，用户自签）、GitHub Actions 云编译流水线、中文教程。

## 2. 已确认的用户事实（不可更改的设计输入）

- 平板与 iPhone **总是随身同时使用**，无需远程服务器/公网。
- 平板有网络（另一台 Oppo 手机开通信共享），**不依赖 iPhone 热点**。
- iPhone 安装方式：免费的全能企业签（证书随时可能失效→App 必须无状态、重装 30 秒恢复）。
- 用户无 Mac，构建必须走云编译。
- 微信/QQ 在平板上已登录同账号，通知回复=平板原生打开对应 App 手动回复。

## 3. 总体架构

```
┌───────────────┐  BLE GATT（平板主动连接，平板=Central）  ┌──────────────┐
│  OPPO Pad 4   │ ───────────────────────────────────▶ │  iPhone 16   │
│  PadLink App  │  1) 配对(Bond)一次，之后自动重连       │  系统 ANCS   │
│  = ANCS 客户端 │  2) 订阅 Notification/Data Source     │  (无需越狱/   │
│  + 通知中心   │  3) ControlPoint 取标题正文/执行动作   │   系统内置)   │
│  + 前台服务   │ ◀─────────────────────────────────── │  助手App可选  │
└───────────────┘        通知内容（分片）                 └──────────────┘
```

**关键决策（已由开源项目 brookwillow/ANCSReader 实证）：**
- 平板扮演 **BLE Central**，主动连接 iPhone；**不需要** Android 侧 GATT server、广播、Service Solicitation UUID。
- iPhone 的 ANCS 由 iOS 系统对**已配对设备**直接提供；核心通知链路**不依赖任何 iPhone App**（配对成功后即使删除 iPhone 端 App 也能收通知）。
- iPhone 端 App 定位为**可选连接助手**：后台广播自定义服务让平板更容易发现/连接 iPhone，并提供状态 UI 与配对引导（双保险，降低真机验证失败风险）。

## 4. ANCS 协议规范（实现依据，来自 Apple 官方文档）

- 服务 UUID：`7905F431-B5CE-4E99-A40F-4B1E122D00D0`
- Notification Source：`9FBF120D-6301-42D9-8C58-25E699A21DBD`（notify，必选）
- Control Point：`69D1D8F3-45E1-49A8-9821-9BBDFDAAD9D9`（write with response）
- Data Source：`22EAC6E9-24D6-4BB5-BE44-B36ACE7C7BFB`（notify）
- CCCD：`00002902-0000-1000-8000-00805f9b34fb`（写 0x0001 使能通知）

**CommandID**：0=GetNotificationAttributes、1=GetAppAttributes、2=PerformNotificationAction。

**Notification Source 事件**（8 字节）：`[EventID(1) | EventFlags(1) | CategoryID(1) | CategoryCount(1) | UID(4B)]`
- EventID：0=Added、1=Modified、2=Removed。判定 Removed 用 `(byte0 & 0x02) != 0`。
- EventFlags：bit0=静默、bit1=重要、bit2=已存在、bit3=正向动作、bit4=负向动作（有动作时 UI 显示按钮）。

**GetNotificationAttributes 请求**（写 Control Point）：`[0x00, UID(4B), 然后每个属性: ID(1B), 可选最大长度(2B)]`。最大长度 `0xFF 0xFF` = 全文。一期取：Title(0x01)+Message(0x03)；二期追加 AppIdentifier(0x00)、Date(0x05)、PositiveActionLabel(0x06)、NegativeActionLabel(0x07)。

**Data Source 响应**（可能按 MTU 分片，**必须重组**）：`[CommandID(1B), UID(4B), 属性三元组序列]`，三元组=`[AttrID(1B), Len(2B 小端), 值(Len B)]`。重组器按"解析到完整三元组即消费，剩余字节留在缓冲区"的增量流式解析。

**PerformNotificationAction 请求**：`[0x02, UID(4B), ActionID(1B)]`，0x00=正向、0x01=负向。

**错误码**：0xA0=未知命令、0xA1=命令格式错误、0xA2=参数无效、0xA3=动作失败。

**会话语义**：订阅 Notification Source 即开会话，NP 会重发当前已有通知；UID/AppIdentifier 仅在会话内有效，断线重连后必须清空本地通知缓存与 UID 映射；同一时刻只允许一个 Control Point 写在途（GATT 写必须串行排队）。

## 5. Android 平板端规格（主工程）

- 目录：`padlink/android/`（工程名 PadLink，包名 `com.padlink.ancs`）
- 语言 Kotlin，compileSdk 35，targetSdk 35，minSdk 26，AGP 8.x，JDK 17，Gradle wrapper 提交到仓库（CI 用 `./gradlew assembleRelease` 无本地 SDK 构建）。
- 依赖仅限 Google/Maven Central 标准库：AndroidX（activity-compose、lifecycle、room 可选）、Material3 Compose。**禁止**任何需要特殊仓库或私有 token 的依赖。

### 5.1 模块
1. **BleCentralService**（前台服务，`foregroundServiceType="connectedDevice"`）：
   - 扫描（用 BluetoothLeScanner，API31+ 加 `ScanSettings` 低功耗/延迟优先，仅首次配对时扫描，配对成功后按已保存地址 `connectGatt`）。
   - 配对：未配对时 `device.createBond()`（iPhone 侧弹确认；或引导用户在系统设置里配对）；配对成功持久化设备地址到 SharedPreferences。
   - 连接与自动重连：指数退避（5s→10s→…→上限 60s），仅在蓝牙开启/屏幕亮起时尝试，连接建立后停止扫描。
   - 连接成功 → discoverServices → 找 ANCS 服务 → 订阅 DataSource+NotificationSource（`setCharacteristicNotification(true)` + 写 CCCD 0x0001，**串行**：先 DataSource 后 NotificationSource，等 onDescriptorWrite 回调再下一步）。
   - `START_STICKY` + onTaskRemoved 重启自身；提供重连/断开 UI 入口。
2. **AncsSession**：
   - 解析 NotificationSource 事件：Removed→本地删除；Added/Modified→向 ControlPoint 排队写 GetNotificationAttributes（Title+Message 一期；二期加 AppIdentifier/Date/动作标签）。
   - ControlPoint 写队列：同一时刻仅一个 GATT 写在途，响应（onCharacteristicWrite GATT_SUCCESS）后出队下一个。
   - DataSource 分片重组器（见 §4），解析出 UID→属性表，合并进通知对象。
   - 会话断开：清空通知缓存与 UID 状态。
3. **NotificationStore**：内存列表 + JSON 文件持久化（一期不引入 Room，降低构建风险）；去重键=UID；上限 200 条环形淘汰；AppIdentifier→图标/名称映射表（见 5.4）。
4. **NotifForwarder**：用 Android `NotificationManager` 发系统通知（渠道 "iPhone通知"），内容=App 名+标题+正文；动作按钮=正向/负向标签（ANCS EventFlags 有动作时）；点击→打开平板本地对应 App（见 5.4）。ANCS 动作按钮点击→`AncsSession.performAction(uid, actionId)` 回写 iPhone。
5. **UI（Compose 单 Activity）**：
   - 配对引导页：扫描结果列表（按名称/服务 UUID 过滤）、"去系统设置配对"入口、配对状态。
   - 状态页：蓝牙开关状态、连接状态、iPhone 名、最近同步时间、省电建议（ColorOS 白名单引导按钮）。
   - 通知中心：列表（应用名、标题、正文摘要、时间）、详情页（全文+动作按钮）、"在平板打开微信/QQ"按钮。
   - 设置页：黑名单 App（不显示）、正文最大长度、自动重连开关、**可选功能：自动连 iPhone 热点（默认关闭）**、自启动/白名单引导。
6. **PhoneLauncher**：AppIdentifier→Android 包名映射表 + 兜底（`getLaunchIntentForPackage`）。

### 5.2 权限（AndroidManifest）
- `BLUETOOTH`（maxSdkVersion=30）、`BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`（API31+，`neverForLocation` 声明可选）、`ACCESS_FINE_LOCATION`+`ACCESS_COARSE_LOCATION`（maxSdkVersion=30，运行时申请）、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`POST_NOTIFICATIONS`（API33+ 运行时申请）、`WAKE_LOCK`（可选）。
- 无需 BLUETOOTH_ADVERTISE。

### 5.3 保活与省电（ColorOS 15 现实约束，UI 内必须有引导页）
- 前台服务 + 常驻通知（低优先级渠道，可隐藏声音）。
- 引导用户：ColorOS「自启动」白名单、电池「允许后台运行」「耗电保护-允许」、后台管理。教程文档配套。

### 5.4 iOS AppIdentifier → Android 包名映射表（一期内置，可扩展）
| iOS bundle id | 应用 | Android 包名 |
|---|---|---|
| com.tencent.xin | 微信 | com.tencent.mm |
| com.tencent.mobileqq | QQ | com.tencent.mobileqq |
| 其他 | 兜底 | 尝试原 id，失败提示"请在平板上手动打开" |

## 6. iPhone 助手 App 规格（可选但推荐，工程目录 `padlink/ios/`）

- Swift + SwiftUI，iOS 15.0+，无第三方依赖，无任何通知读取。
- 功能：
  1. `CBPeripheralManager` 后台广播自定义服务 UUID `5E3F6A11-2C4D-4B7E-9A10-1F2E3D4C5B6A`（同时填 localName "PadLink-Phone"）。
  2. `Info.plist` → `UIBackgroundModes: bluetooth-peripheral`；`CBPeripheralManagerOptionRestoreIdentifierKey` 状态恢复。
  3. UI：广播状态、蓝牙开关状态、配对引导（三步图文）、"iPhone 重启后需打开本 App 一次"提示、掉线自恢复状态。
  4. 无状态：不存任何数据，删除重装即恢复（适配企业签失效）。
- 说明：ANCS 由 iOS 系统提供，本 App **不读通知、不经手通知内容**，只是让 iPhone 在后台保持可被发现/可连接。
- 构建：CI 上 `CODE_SIGNING_ALLOWED=NO` 出**未签名** .app → 打包 Payload/*.app → zip → 改名 .ipa（脚本 `padlink/ios/scripts/package_ipa.sh`）。

## 7. CI/CD（GitHub Actions，`padlink/.github/workflows/`）

- `android.yml`（ubuntu-latest，JDK 17）：`./gradlew assembleRelease`；签名：仓库内 `android/signing/` 提供 release keystore（个人项目，密码写入仓库文档即可）或回退 debug 签名；上传 APK artifact。
- `ios.yml`（macos-14）：`xcodebuild -project ... -scheme PadLink -configuration Release -archivePath ... archive CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY="" CODE_SIGNING_REQUIRED=NO` → `scripts/package_ipa.sh` → 上传未签名 ipa artifact（用户用全能签自签）。
- 两个 workflow 都支持 `workflow_dispatch` 手动触发 + tag `v*` 自动触发。

## 8. 三期计划

- **一期（本阶段）**：真机最小验证包 = 平板 App 完整可装 APK（配对→连接→收通知→列表显示）+ iPhone 助手可装 ipa + 双流水线 + 安装教程。用户真机验证 ANCS 链路（含 iPhone 侧开启设备"共享系统通知"开关——**必须写进教程**）。
- **二期**：通知中心打磨（App 图标/名称、动作按钮回写、黑名单、历史搜索）、保活调优。
- **三期**：可选自动连热点（默认关）、耗电优化、多语言。

## 9. 已知限制（必须诚实呈现给用户，写入教程 FAQ）

1. iOS 不允许第三方 App 读其他 App 通知，ANCS 是唯一合法通道（内容只有标题/正文/动作，无图片附件）。
2. 无法替 iPhone 批量清除/标记已读通知；只能执行 ANCS 提供的一两个动作。
3. 点击平板通知无法远程打开 iPhone App，只能在平板本地打开对应 App。
4. iPhone 重启后 ANCS 会话需重新建立（平板自动重连），iPhone 助手 App 需手动打开一次。
5. 企业签失效需重装（App 无状态，重装即恢复）。
6. iPhone 端功耗约 1-3%/天。
7. ColorOS 后台限制严格，需按教程配置白名单。
