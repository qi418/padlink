# PadLink 排障指南

真机验收遇到问题时，按「现象 → 原因 → 处理」对照排查。大部分问题属于手机/平板系统的省电与权限策略，按对应条目操作一次即可长期生效。

---

## 一、平板端（PadLink）

### 1. 扫描不到我的 iPhone
| 可能原因 | 处理 |
|---|---|
| 平板蓝牙未开启 | 打开平板蓝牙（App 配对页有「去系统设置配对」入口） |
| 蓝牙权限未授予 | 首次启动应弹出权限申请；若拒绝过：系统设置 → 应用 → PadLink → 权限 → 授予「附近的设备/蓝牙」与「通知」 |
| iPhone 蓝牙没在设置页打开 | 把 iPhone 停在「设置 → 蓝牙」页面再扫描（iOS 只有在此页面才全力广播） |
| iPhone 后台广播被系统暂停 | 打开一次 iPhone 上的 PadLinkHelper，让广播恢复 |
| 距离太远 | 两设备保持 1 米内 |

### 2. 点了「配对」但没反应 / 配对失败
- 确认 iPhone 屏幕上弹出配对请求后点了「配对」，并核对两端 6 位配对码一致。
- 若 iPhone 端点了「取消」或超时：重新扫描再点一次「配对」。

### 3. 之前能连，后来连不上
- iPhone 地址随机化 + 用户曾在 iPhone 上「忽略此设备」：在 PadLink 配对页点「忘记此设备」，重新扫描配对一次即可。

### 4. 已连接但提示「未找到 ANCS 服务」
这是最常见的验证卡点，含义：平板已连上设备，但该设备没有暴露 ANCS，或配对不是系统级配对。

按顺序检查：
1. **连接的是不是 iPhone**（不要误连耳机/手环等）。
2. **iPhone「设置 → 蓝牙」里是否真的显示已与平板配对**。若只是 App 内点了配对而未在 iPhone 上确认，请取消后重来。
3. ANCS 即 iOS「共享系统通知」，**无需在 iPhone 上安装任何 App**；若 iOS 提示「是否允许该设备访问你的通知」之类弹窗，必须点「允许」。
4. 尝试：iPhone 蓝牙关→开一次，平板断开→重连一次。
5. 仍不行：重启 iPhone 再试（iOS 偶尔在会话后不重建 GATT 服务）。

### 5. 显示「已连接 ✓」但收不到通知
按概率从高到低：

| 可能原因 | 处理 |
|---|---|
| 平板通知权限未授予 | 系统设置 → 应用 → PadLink → 通知 → 允许 |
| ColorOS 把后台服务杀了 | 见第 6 条白名单设置 |
| 该 App 被拉黑 | PadLink「设置」页黑名单里关闭对应 App |
| 该通知本身是「静默通知」 | 静默通知（无横幅的推送）按设计不转发，属正常 |
| iPhone 该 App 通知关了 | iPhone 设置 → 通知 → 对应 App → 允许通知 |
| 系统通知渠道被 ROM 折叠 | 下拉通知栏 → PadLink 的「iPhone通知」渠道 → 设为「重要/全部显示」 |

### 6. 锁屏或清理后台后断连/漏通知（ColorOS 保活）
PadLink 是前台服务，但国产 ROM 仍可能杀。一次性设置：

1. 手机管家/安全中心 → 应用管理 → 自启动管理 → **允许 PadLink 自启动**；
2. 电池 → 应用耗电管理 → PadLink → **允许后台运行 / 不限制**；
3. 多任务界面把 PadLink 卡片**下拉锁定**；
4. 通知栏里 PadLink 的常驻服务通知**不要划掉**。

完成后重启一次 PadLink。

### 7. 通知详情里没有微信/QQ 按钮或动作按钮
- 原因：iOS 未返回 AppIdentifier / 动作标签（部分 iOS 版本对扩展属性返回错误码 0xA0-0xA3）。基础转发不受影响，属容错降级。
- 处理：确认 iPhone 该 App 的通知样式为「横幅/提醒」而非「仅锁屏」；升级 iOS 至最新；仍无则等待迭代（二期增加 App 映射手动指定）。

### 8. 断线重连后通知中心被清空
- 这是 ANCS 协议会话语义（通知 ID 断线即作废），属设计行为，无法保留历史。

### 9. 抓日志（排查时给我看这个）
Windows 电脑连上平板（开发者模式 + USB 调试）后：

```
adb logcat -v time PadLink:V BluetoothGatt:D BluetoothLeScanner:D *:S
```

复现问题后把输出发我，可精确定位卡点。

## 二、iPhone 端（PadLinkHelper）

### 1. ipa 装不上 / 打开闪退
- 企业签证书失效（随时可能挂）：换签名源重新签一次再装；App 无状态，重装不影响平板已建立的配对。
- 装完后若提示「未受信任的开发者」：设置 → 通用 → VPN 与设备管理 → 信任对应证书描述文件。

### 2. 状态卡显示「广播异常/已停止」
- iOS 省电暂停了后台广播：打开 PadLinkHelper 一次即恢复；属系统行为，不影响已配对后的通知链路。

### 3. iPhone 重启后平板连不上了
- iOS 不会自动启动普通 App：打开一次 PadLinkHelper 恢复广播（系统配对本身仍在，通知链路在广播恢复前也可能自动重连）。

## 三、云编译（GitHub Actions）

### 1. Android 流水线失败
- 看 Build release APK 步骤日志：首次运行会自动下载 Gradle 8.11.1 + 全部依赖（约 3-5 分钟），超时/网络错误直接重跑一次。
- 报编译错误：把报错行发我。

### 2. iOS 流水线失败
- 常见报错：`xcodebuild: error: The project ... does not contain a scheme named "PadLinkHelper"` → 确认 `PadLinkHelper.xcodeproj/xcshareddata/xcschemes/PadLinkHelper.xcscheme` 已随仓库提交（不要用 .gitignore 排除）。
- 报 pbxproj 解析错误 → 把报错行号发我，按行修复即可（工程为 Windows 手写生成，未在 Mac 本地编译过，首次 CI 是第一次真编译）。

### 3. 下载产物
- Actions → 对应流水线运行 → 底部 Artifacts：`PadLink-APK`（平板装这个 release 包）、`PadLinkHelper-unsigned-IPA`（拿去签名）。
